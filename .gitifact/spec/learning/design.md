# 학습 설계

## 개요

학습·문제풀이용 DB 를 되돌리는 버튼의 이름과 설명을 분명히 하고, 데이터를 바꾼 예제를 실행했을 때 그 사실을 보여 준다.

## 구조와 데이터

- 워커의 `exec` 결과에 `changed`(실행 전후 change token 비교)를 실어 화면이 데이터 변경 여부를 안다. 스냅샷을 찍지 않으므로 비용이 거의 없다.
- `LearnView` 는 `dirty` 상태 하나로 "바꾸는 예제를 실행한 적이 있는지" 를 기억하고, 되돌리기에서 초기화한다. 저장하지 않는다. 새로고침하면 학습용 DB 도 새로 실리므로 같이 초기 상태가 된다.
- `RunnableSql` 은 자기 실행의 `changed` 를 받아 결과 아래에 안내를 붙인다.

## 처리 흐름

<!-- gitifact-ref: R-bj2oscebzh -->

- 예제 실행 → 컨텍스트 `run()` → `{ outcome, changed }` → changed 면 블록 안내 + 화면 `dirty`.
- 되돌리기 → 학습용 엔진 reset + 샘플 재로드 + `checkpoint()` → dirty 해제 → 예제 블록 key 갱신으로 결과 초기화.

## 주요 설계 결정

- 이름을 "예제 DB 초기화" 에서 "샘플 데이터 되돌리기" 로 바꾼 이유: "예제 DB" 라는 말이 화면 어디에도 설명돼 있지 않아 연습장까지 지워지는지 헷갈렸다.
- 변경 여부를 exec 결과에 넣은 이유: 학습 예제에 `run()`(스냅샷 포함)을 쓰면 실행마다 DB 전체를 전송해야 한다. change token 비교는 워커 안에서 끝난다.
