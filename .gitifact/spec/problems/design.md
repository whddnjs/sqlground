# 문제풀이 설계

## 개요

문제 화면이 "무엇을 요구하는지" 와 "풀고 난 뒤 배울 것" 을 함께 보여 주도록 한다. 콘텐츠는 단원당 쉬움·보통·어려움 3문제로 다시 짰다 (62문제).

## 구조와 데이터

- `problems/types.ts`: `Problem` 에 `answerNote`(모범 답안 설명)와 `alternatives`(sql + note)를 둔다. 데이터 변경 문제는 기존대로 `checkSql`.
- `problems/context.ts`: 문제가 쓰는 테이블을 정답·확인 쿼리에서 뽑고(`relatedTables`, 에디터 자동완성과 같은 `tablesMentioned`), 각 테이블의 앞 5행과 전체 행 수를 읽는다(`loadTablePreviews`). 컬럼 설명은 샘플 프리셋의 설명을 합친 `SAMPLE_DESCRIPTIONS`. `lastQueryResult` 는 채점과 미리보기가 함께 쓴다.
- `components/problems/`: `DataPreview`(작은 표), `ProblemContext`(관련 테이블, 항상 표시), `SectionPanel`(에디터 아래 영역의 공통 틀: 색 띠·아이콘·제목·닫기), `ExpectedResult`(기대 결과 내용), `SolutionPanel`(모범 답안 + 다른 풀이 내용).
- `ProblemsView`: `context` 상태에 { 문제 id, 테이블 미리보기, 기대 결과 } 를 둔다.

## 처리 흐름

<!-- gitifact-ref: R-6o5o3j7g73, R-ac4wuvaxgn, R-pvef37nppx -->

- 문제를 열면 effect 가 관련 테이블 미리보기를 읽고, 채점과 같은 경로(`execute`)로 정답을 실행해 기대 결과를 만든다. 변경 문제는 스냅샷 → 실행 → 확인 쿼리 → 복원.
- 이 준비가 끝나기 전에는 실행·제출을 막는다(`contextReady`). 변경 문제의 격리 실행 도중 사용자의 실행이 끼어들면 DB 상태가 섞이기 때문이다.
- DB 되돌리기와 "사용자가 데이터를 바꾼 실행" 은 `dataVersion` 을 올려 맥락을 다시 불러온다.
- 화면 순서: 설명 → 관련 테이블 → 에디터(실행·제출 / 힌트 · 기대 결과 · 정답 보기) → 에디터 아래 패널들. 도움은 힌트 → 기대 결과 → 정답 쿼리 순으로 강해진다.
- 에디터 아래는 종류마다 제목이 있는 패널(`SectionPanel`)로 나눈다: 힌트(노랑) → 내 실행 결과(정답 초록 / 오답 빨강 / 단순 실행 회색, 판정은 제목에 "· 정답/오답" 으로 붙이고 메시지는 패널 안 맨 위) → 기대 결과(남색, 제목 옆에 행·열 수) → 모범 답안과 다른 풀이(보라). 패널은 `region` 역할과 제목을 이름으로 가져 보조 기술과 e2e 가 같은 이름으로 찾는다.
- 판정은 "그 제출" 에만 붙는다. 제출 뒤에 그냥 실행하면 지난 판정(색·제목·메시지)을 지우고 결과 패널을 기본 회색으로 되돌린다. 오답 표시가 남은 채 새 결과가 나오면 새 결과까지 오답처럼 보이기 때문이다(사용자 요청). 정답을 맞혀 열린 모범 답안은 판정이 지워져도 닫히지 않게 "정답 보기" 상태로 넘긴다.
- 도움 버튼은 토글이고 켜져 있으면 패널과 같은 색으로 표시한다(`aria-pressed`). 패널의 닫기 버튼도 같은 상태를 끈다. 패널이 새로 나타나거나 다시 실행하면 그 패널로 스크롤한다(`scrollKey`).

## 진행도와 이어 풀기

<!-- gitifact-ref: R-4xrdj5mnem -->

- 해결 기록은 기존 `problem-store` 의 `solved` 를 그대로 쓴다. 장별 해결 수는 렌더 때 `GROUPS` 와 대조해 센다(따로 저장하지 않는다).
- `nextUnsolved(fromId, solved)`: 문제 순서(`ORDERED`)에서 fromId 다음부터 한 바퀴 돌며 안 푼 첫 문제를 찾는다. 정답 패널의 "다음 문제" 버튼과 목록 아래 "모두 해결" 표시가 쓴다. 목록 아래에도 같은 함수로 "이어 풀기" 버튼을 뒀었으나, 푼 문제가 없을 때는 "다음" 과 구분되지 않아 헷갈린다는 사용자 판단으로 뺐다.
- 진행 막대는 `role="progressbar"` 로 두어 보조 기술과 테스트가 현재 값을 읽는다.

## 종합 문제

<!-- gitifact-ref: R-wmleufsvbg -->

- `Problem.mixes`(단원 id 2개 이상)가 있으면 종합 문제다. `lessonId` 는 `mixes` 의 첫 단원이며, 어느 장에 속하는지는 이 단원의 장으로 정한다. 별도 `chapterId` 를 두지 않아 기존 필드와 목록 묶기 코드를 그대로 쓴다.
- 문제 목록은 `SECTIONS`(장 → 단원 소묶음) 뒤에 "종합 문제" 장을 하나 더 두고, 그 안을 원래 장 이름으로 나눈다. 처음엔 각 장 끝에 "종합" 소제목을 끼웠는데 목록이 지저분해 사용자 결정으로 맨 끝 별도 장으로 옮겼다. `ORDERED` 는 단원 문제 전부 다음에 종합 문제가 온다.
- 관련 단원은 `mixes ?? [lessonId]` 를 링크 목록으로 보여 준다.
- 학습 화면은 장의 마지막 단원에서만 그 장의 종합 문제를 "○○ 종합 문제" 로 보여 준다(`ProblemLinks` 부품을 단원 문제와 공유).
- 테스트 규칙: 종합 문제는 장마다 3개, 보통 이상, 난이도 오름차순, 단원 2개 이상(겹침 없음)이며 뒤 장의 단원은 쓰지 않는다. 설명에 "단원을 씁니다" 로 쓰는 단원을 적는다. 단원당 3문제 규칙은 mixes 없는 문제만 센다.

## 답안 SQL 표시

- 콘텐츠의 `answerSql`·`alternatives[].sql`·`checkSql` 은 채점과 테스트가 다루기 쉽게 **한 줄**로 둔다. 화면에 보여 줄 때만 `lib/format-sql.ts`(sql-formatter, sqlite 방언, 키워드 대소문자 유지, 키워드를 오른쪽 끝에 맞추는 `tabularRight`)로 줄 바꿈·들여쓰기를 정리한다. tabularRight 는 가장 긴 키워드(LEFT JOIN) 폭에 맞춰 앞에 빈칸을 두므로 문장마다 공통 앞 빈칸을 걷어낸다. 스타일은 사용자가 기본·tabularLeft·tabularRight 출력을 비교해 골랐다(세로 길이가 짧고 절 구조가 한눈에 보임). 포맷터가 못 읽는 문장은 원문 그대로.
- 표시는 `components/editor/SqlBlock`: 읽기 전용 CodeMirror 로 에디터와 같은 색으로 강조한다. `role="figure"` 와 이름을 두어 테스트가 찾는다. e2e 헬퍼 `setEditor` 는 편집 가능한 `.cm-content` 만 세므로 읽기 전용 블록이 위에 있어도 엇갈리지 않는다.

## 오류 처리와 검증

- 관련 테이블이 아직 없는 문제(CREATE TABLE)는 참조하는 기존 테이블만 보여 주거나 패널을 생략한다.
- 단위 테스트(`problems.test.ts`): 모범 답안 실행과 결과 존재, 다른 풀이가 모범 답안과 같은 채점 결과, 변경 문제는 아무것도 안 하면 오답, 단원별 난이도 순서와 단원당 최대 3문제, 조회 문제 설명의 "결과 열:" 표기.
- e2e: 관련 테이블과 기대 결과가 보이고 정답 쿼리는 숨겨짐, 정답 제출 후 모범 답안과 다른 풀이 표시.

## 주요 설계 결정

- 기대 결과는 처음엔 기본 표시였으나 사용자 결정으로 버튼 뒤(힌트와 정답 보기 사이)로 옮겼다. 결과를 미리 보면 스스로 생각할 여지가 줄어든다는 판단이다. 관련 테이블은 문제 이해에 꼭 필요해 기본 표시로 남겼다.
- 관련 테이블을 문제마다 적지 않고 정답 쿼리에서 뽑는 이유: 62문제에 손으로 적으면 어긋나기 쉽다.
- 자동 패턴 감지를 넣지 않은 이유: 요구사항의 범위와 제약 참고. 대신 작성한 다른 풀이를 테스트로 검증한다.
- 단원당 3문제로 맞추며 비슷한 쉬운 문제는 정리했다. 사라진 문제의 해결 기록은 브라우저에 남아 있어도 무해하다.
- 에디터 아래 영역을 색 띠와 제목이 있는 패널로 나눈 이유: 힌트·기대 결과·내 결과·모범 답안이 비슷한 표와 글로 이어져 "기대 결과" 표와 "내 결과" 표를 헷갈리기 쉬웠다. 판정을 별도 상자로 두지 않고 결과 패널 제목에 합쳐 상자 수를 줄였다.
- 패널은 도움의 세기 순이 아니라 쓰는 흐름대로 놓는다: 가장 자주 보는 내 실행 결과를 에디터 가까이에 두고, 오답일 때 비교하는 기대 결과를 그 바로 아래에 붙인다. 힌트는 한두 줄이라 맨 위에 두어도 결과를 밀어내지 않고, 긴 모범 답안은 맨 아래로 보낸다. 처음에는 내 결과가 맨 아래였는데 도움 패널을 열수록 실행할 때마다 크게 스크롤해야 했다.
