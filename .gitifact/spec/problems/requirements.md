# 문제풀이 요구사항

## 힌트와 정답은 언제든 볼 수 있다
<!-- gitifact-req: R-xidbllh2c7 -->

SQL 을 배우는 사용자로서, 막혔을 때 스스로 정한 순간에 답을 참고하기 위해 힌트와 정답을 제한 없이 볼 수 있기를 바란다.

### 수용 조건

1. 조건: 문제를 열자마자 힌트 또는 정답 보기를 누릅니다.
   기대 동작: 제출 여부와 관계없이 힌트 문장 또는 정답 쿼리가 바로 표시됩니다.
2. 조건: 정답을 본 뒤 그 쿼리를 그대로 제출합니다.
   기대 동작: 보통 제출과 똑같이 채점되고, 맞으면 해결로 표시됩니다. 정답을 봤다는 이유로 불이익이나 별도 표시는 없습니다.
3. 조건: 다른 문제로 이동했다가 돌아옵니다.
   기대 동작: 힌트와 정답은 다시 접힌 상태로 시작하며, 언제든 다시 열 수 있습니다.

### 범위와 제약

- 학습이 목적인 사이트이므로 정답을 보는 것도 학습으로 본다. "먼저 시도하게 강제" 는 하지 않는다 (2026-09-18 결정).

## 문제에 쓰이는 테이블과 기대 결과 보여 주기
<!-- gitifact-req: R-6o5o3j7g73 -->

SQL 을 배우는 사용자로서, 문제가 무엇을 요구하는지 헤매지 않기 위해 문제에 쓰이는 테이블을 문제 옆에서 바로 보고, 막히면 기대하는 결과를 열어 보고 싶다.

### 수용 조건

1. 조건: 문제를 엽니다.
   기대 동작: 그 문제가 쓰는 테이블마다 컬럼 이름, 타입, 기본키·외래키 표시, 컬럼 한글 설명, 데이터 앞 5행과 전체 행 수가 보입니다. 전체 조회를 따로 해 보지 않아도 컬럼 이름을 알 수 있습니다.
2. 조건: 조회 문제에서 에디터 아래의 "기대 결과" 버튼을 누릅니다. 버튼은 힌트와 정답 보기 사이에 있습니다.
   기대 동작: 정답 쿼리를 실행한 결과가 에디터 아래에 "이런 결과가 나와야 해요" 로 나타납니다. 앞 8행과 전체 행·열 수가 나오고, 행 순서까지 맞아야 하는 문제는 그 사실이 함께 표시됩니다. 정답 쿼리 자체는 보이지 않습니다. 다시 누르면 접힙니다. 처음에는 접혀 있습니다.
3. 조건: 데이터 변경 문제에서 같은 버튼을 누릅니다.
   기대 동작: 정답을 실행한 뒤 확인 쿼리로 본 결과가 "정답을 실행하면 이렇게 바뀌어야 해요" 로 표시됩니다.
4. 조건: 테이블에 없는 값(등급, 가격대 등)을 직접 만들어야 하는 문제입니다.
   기대 동작: 설명에 그 값이 테이블에 없으며 직접 만들어야 한다는 점과 만드는 규칙이 적혀 있습니다.
5. 조건: 되돌리기를 누르거나 사용자가 데이터를 바꾸는 SQL 을 실행합니다.
   기대 동작: 테이블 미리보기와 기대 결과가 현재 데이터 기준으로 다시 계산됩니다.

### 범위와 제약

- 모든 조회 문제의 설명에는 결과 열을 순서대로 적는다.

## 모범 답안과 다른 풀이
<!-- gitifact-req: R-ac4wuvaxgn -->

SQL 을 배우는 사용자로서, 같은 결과를 내는 여러 방법과 그 차이를 익히기 위해 문제를 푼 뒤 모범 답안과 다른 풀이를 설명과 함께 보고 싶다.

### 수용 조건

1. 조건: 정답을 제출했거나 정답 보기를 눌렀습니다.
   기대 동작: 판정과 내 결과 아래에 모범 답안이 나오고, 답안을 왜 그렇게 썼는지 설명이 있으면 함께 보입니다.
2. 조건: 답이 여러 개 나올 만한 문제입니다(예: OR 와 IN, LEFT JOIN 과 NOT EXISTS).
   기대 동작: "다른 풀이" 가 각각 언제 더 나은지, 어떤 함정이 있는지 설명과 함께 나열됩니다.
3. 조건: 답이 사실상 하나뿐인 문제입니다.
   기대 동작: 다른 풀이 없이 모범 답안만 나옵니다.

### 범위와 제약

- 사용자가 제출한 SQL 을 분석해 개선점을 자동으로 지적하지는 않는다. 문자열 검사로는 오탐이 나기 쉽고 틀린 조언은 없는 것보다 나쁘다 (2026-09-18 결정).
- 다른 풀이는 모범 답안과 채점 결과가 같아야 하며 테스트로 검증한다.

## 단원별 3문제 구성
<!-- gitifact-req: R-pvef37nppx -->

SQL 을 배우는 사용자로서, 단원을 배운 직후 난이도를 차례로 올려 가며 연습하기 위해 문제가 단원별로 고르게 짜여 있기를 바란다.

### 수용 조건

1. 조건: 문제 목록을 봅니다.
   기대 동작: 문제가 학습 단원 순서로 묶여 있고, 단원 안에서는 쉬움 → 보통 → 어려움 순으로 놓여 있습니다.
2. 조건: 연습 문제가 어울리는 단원입니다.
   기대 동작: 쉬움·보통·어려움이 하나씩, 단원당 3문제가 있습니다.
3. 조건: 개념 소개 단원이거나 결과 비교로 채점하기 어려운 단원입니다(SQL 이란, 트랜잭션, 뷰와 인덱스 등).
   기대 동작: 문제가 없거나 1~2문제만 있습니다.

### 범위와 제약

- 쇼핑몰·학교·회사 세 샘플을 고르게 쓴다.

## 진행도와 다음 문제
<!-- gitifact-req: R-4xrdj5mnem -->

SQL 을 배우는 사용자로서, 62문제를 끝까지 풀어 나가기 위해 어디까지 풀었는지를 목록에서 바로 알고, 맞힌 뒤에는 다음에 풀 문제로 바로 넘어가고 싶다.

### 수용 조건

1. 조건: 문제 목록을 봅니다.
   기대 동작: 장마다 "해결 수/문제 수" 가 제목 옆에 보이고, 목록 아래에 전체 해결 수와 진행 막대가 있습니다. 한 장을 다 풀면 그 장의 숫자가 초록으로 바뀝니다.
2. 조건: 문제를 맞힙니다.
   기대 동작: 정답 메시지 옆에 다음에 풀 문제(지금 문제 다음부터, 끝에 닿으면 처음부터, 아직 풀지 않은 첫 문제)로 가는 버튼이 나옵니다. 모든 문제를 풀었으면 버튼 대신 다 풀었다는 표시가 나오고, 목록 아래에도 "모두 해결" 이 보입니다.

### 범위와 제약

- 진행 기록은 지금처럼 이 브라우저에만 저장된다. 기기 간 동기화는 로그인 기능(나중 범위)에서 다룬다.

## 장별 종합 문제
<!-- gitifact-req: R-wmleufsvbg -->

SQL 을 배우는 사용자로서, 한 장을 마친 뒤 배운 것들을 한 문제 안에서 함께 써 보기 위해 여러 단원을 섞은 종합 문제를 풀고 싶다.

### 수용 조건

1. 조건: 문제 목록을 봅니다.
   기대 동작: 단원별 문제 목록은 그대로이고, 맨 끝에 "종합 문제" 장이 따로 있습니다. 그 안은 원래 장 이름(데이터 조회, 집계와 그룹 …)으로 나뉘고 장마다 3문제(보통 1, 어려움 2)가 있습니다. 개념만 다루는 시작하기 장의 종합 문제는 없습니다.
2. 조건: 종합 문제를 엽니다.
   기대 동작: 설명 끝에 어떤 단원들을 쓰는지 적혀 있고, "관련 단원" 에 그 단원들이 모두 링크로 보입니다.
3. 조건: 학습에서 한 장의 마지막 단원을 봅니다.
   기대 동작: 단원 문제 아래에 "이 장 종합 문제" 가 따로 보입니다.
4. 조건: 종합 문제를 풉니다.
   기대 동작: 그 장의 단원을 포함해 단원 2개 이상을 써야 풀리며, 채점·힌트·기대 결과·모범 답안은 다른 문제와 같습니다.

### 범위와 제약

- 앞 장에서 배운 단원은 섞어도 되지만 뒤 장의 단원은 쓰지 않는다.
- 종합 문제는 단원당 3문제 규칙과 별개로 센다.
