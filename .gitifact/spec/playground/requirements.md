# 연습장 보조 동작 요구사항

## 되돌리기 어려운 조작 전 확인
<!-- gitifact-req: R-dvgxorusdo -->

SQL 을 배우는 사용자로서, 실수로 테이블이나 데이터를 잃지 않기 위해 되돌리기 어려운 조작 전에 무엇이 실행되는지 보고 확인하고 싶다.

### 수용 조건

1. 조건: 사용자가 테이블 삭제, 행 삭제(한 행·여러 행), 컬럼 삭제, DB 초기화, 같은 이름의 테이블이 있는 상태에서 샘플 로드, 내용이 있는 쿼리 탭 닫기, DB 파일 가져오기 중 하나를 요청합니다.
   기대 동작: 시스템은 앱 안의 확인창을 띄워 무엇이 일어나는지 설명하고, SQL 이 실행되는 조작이면 그 SQL 을 그대로 보여 준 뒤 확인을 기다립니다. 브라우저 기본 확인창은 쓰지 않습니다.
2. 조건: 사용자가 확인창에서 취소하거나 Esc 를 누릅니다.
   기대 동작: 시스템은 아무것도 실행하지 않고 원래 상태를 유지합니다.
3. 조건: 사용자가 확인합니다.
   기대 동작: 시스템은 해당 조작을 실행하고, 되돌리기로 복구할 수 있는 조작이면 확인창에서 그 사실을 미리 알려 줍니다.
4. 조건: 내용이 비어 있는 쿼리 탭을 닫습니다.
   기대 동작: 잃을 내용이 없으므로 확인 없이 바로 닫힙니다.
5. 조건: DB 파일 가져오기에 실패합니다(깨진 파일 등).
   기대 동작: 시스템은 앱 안의 알림창으로 실패 이유를 보여 주고 기존 DB 를 그대로 둡니다.

## 빈 DB 의 시작 안내
<!-- gitifact-req: R-maywmhfqwe -->

처음 방문한 사용자로서, 무엇부터 해야 할지 헤매지 않기 위해 빈 화면에서 바로 시작할 수 있는 안내를 보고 싶다.

### 수용 조건

1. 조건: 연습장에 테이블이 하나도 없고 아직 실행 결과도 없습니다.
   기대 동작: 결과 영역에 시작 안내가 나타나며, 샘플 데이터(쇼핑몰·학교·회사) 로드, 에디터의 예시 쿼리 실행, 학습으로 이동 세 가지를 한 번의 클릭으로 할 수 있습니다.
2. 조건: 안내에서 샘플을 고릅니다.
   기대 동작: 헤더의 샘플 로드와 같은 규칙으로 로드되며(같은 이름의 테이블이 있으면 확인), 테이블이 생기면 안내는 사라집니다.
3. 조건: 테이블이 하나라도 있거나 실행 결과가 있습니다.
   기대 동작: 시작 안내는 보이지 않습니다.

## 실행 이력 유지
<!-- gitifact-req: R-uhchn26c4c -->

SQL 을 배우는 사용자로서, 이전에 실행한 쿼리를 다시 찾아 쓰기 위해 실행 이력이 새로고침 뒤에도 남아 있기를 바란다.

### 수용 조건

1. 조건: 사용자가 연습장에서 쿼리를 실행(에디터, UI 조작, 샘플 로드 포함)한 뒤 페이지를 새로고침합니다.
   기대 동작: 히스토리 탭에 이전 이력이 실행 순서와 출처(에디터·UI·샘플), 성공 여부와 함께 그대로 남아 있습니다.
2. 조건: 이력이 100개를 넘습니다.
   기대 동작: 가장 오래된 것부터 지워져 최근 100개만 유지됩니다.
3. 조건: 저장된 이력이 손상돼 있습니다.
   기대 동작: 손상된 항목만 버리고 나머지는 보여 주며, 화면은 정상 동작합니다.

### 범위와 제약

- 이력은 사용자의 브라우저에만 저장된다. 다른 기기와 공유되지 않는다.
