# 연습장 보조 동작 설계

## 개요

연습장의 세 가지 보조 동작을 다룬다. 파괴적 조작 전 확인, 빈 DB 의 시작 안내, 실행 이력 유지. 셋 다 화면 계층의 변경이며 엔진은 건드리지 않는다.

## 구조와 데이터

- **확인창**: `store/confirm-store.ts` 가 `confirm(options)`, `alert(options)` 를 Promise 로 제공하고, `components/ui/ConfirmHost.tsx` 가 App 에 한 번 놓여 대기 중인 요청을 `<dialog>` 로 그린다. 호출부는 결과를 기다렸다가 실행한다. 옵션은 제목, 설명, 실행될 SQL, 확인 버튼 문구, 위험 여부, 되돌리기 가능 여부.
- **시작 안내**: `components/result/WelcomeCard.tsx`. 결과 패널이 "결과 없음 · 알림 없음 · 테이블 없음" 일 때만 그린다. 샘플 로드는 헤더와 같은 `lib/use-preset-loader.ts` 훅을 써서 덮어쓰기 확인 규칙을 공유한다.
- **이력**: `store/db-store.ts` 의 history 를 `localStorage` 키 `sqlground:history` 에 저장한다. 항목은 id, sql, source, ok, at. 읽을 때 `lib/storage.ts` 의 검증 헬퍼로 형식이 맞는 항목만 남기고, 다음 id 는 저장된 최대값 다음부터 잇는다.

## 처리 흐름

<!-- gitifact-ref: R-dvgxorusdo, R-maywmhfqwe, R-uhchn26c4c -->

- 파괴적 조작: 호출부가 SQL 을 만든 뒤 `confirm({ sql, danger, undoable })` → 사용자가 확인하면 그때 실행. 취소·Esc·닫기는 모두 false 로 해결된다. 새 요청이 들어오면 열려 있던 것은 취소로 닫힌다.
- 시작 안내: 샘플 버튼 → 프리셋 로더 → 테이블 생김 → 조건이 깨져 카드가 사라진다. 예시 실행은 활성 탭의 코드를 그대로 실행한다.
- 이력: 실행이 끝나 이력을 기록할 때마다 최근 100개를 통째로 저장한다. 시작 시 한 번 읽어 스토어 초기값으로 쓴다.

## 오류 처리와 검증

- 저장소 접근 불가(사생활 보호 모드 등)면 이력 저장은 조용히 건너뛴다.
- 손상된 이력 항목은 필드 타입 검사로 걸러 낸다.
- e2e: 테이블 삭제 확인창에 SQL 이 보이고 취소 시 유지·확인 시 삭제, 빈 DB 의 시작 카드 표시와 샘플 로드 후 사라짐, 새로고침 후 이력 유지.

## 주요 설계 결정

- 확인창을 전역 Promise 함수로 둔 이유: 호출부가 9곳으로 흩어져 있어 각 컴포넌트에 열림 상태를 두면 반복이 크다. 스토어 밖(훅, 헬퍼)에서도 부를 수 있어야 했다. 대안이었던 컴포넌트별 상태는 기각.
- 시작 안내를 별도 저장 없이 "테이블 없음" 조건으로만 판단한 이유: 닫기 상태를 따로 기억하면 초기화 뒤에 안내가 다시 안 나온다. 조건 기반이면 초기화 뒤에도 자연스럽게 다시 보인다.
- 이력을 IndexedDB 의 DB 바이너리와 분리해 localStorage 에 둔 이유: 이력은 작고 텍스트라 동기 저장이 간단하며, DB 초기화와 무관하게 남아야 한다.
